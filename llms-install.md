# Установка attest для агента

Одна строка — сервер поднимается, ключи и регистрация не нужны.

```bash
claude mcp add --transport http attest https://attest.rta.lat/mcp
```

Или блок в конфиг MCP-клиента:

```json
{
  "mcpServers": {
    "attest": { "url": "https://attest.rta.lat/mcp" }
  }
}
```

Проверка, что всё живо:

```bash
curl -s https://attest.rta.lat/health
# {"status":"ok","version":"0.1.0"}
```

Список инструментов:

```bash
curl -s -X POST https://attest.rta.lat/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## Инструменты

### `verify_artifact` — проверить артефакт агента **до выплаты**

| Аргумент | Обязательный | Что это |
|---|---|---|
| `artifact` | да | объект, массив или строка |
| `schema` | нет | JSON Schema, которому артефакт должен соответствовать |
| `source` | нет | откуда артефакт — попадает в подпись |

Четыре слоя: схема, пустота (одинаковые пункты, заглушки, обрезанный вывод),
привязка к условиям генерации, право действовать по подписанному мандату.
Ответ: вердикт (`accept` / `review` / `reject`), доверие 0–100, конкретные
находки и подпись Ed25519.

### `verify_artifact_batch` — та же проверка пачкой

| Аргумент | Обязательный | Что это |
|---|---|---|
| `artifacts` | да | массив артефактов (до 50) |
| `schema` | нет | схема на каждый |
| `source` | нет | откуда пришли |

Вердикт на каждый артефакт плюс сводка: сколько принято, сколько на
проверку, сколько отклонено.

### `bridge_check` — расчёт между агентами

Действия: `job` (создать задачу с бюджетом в эскроу), `deliver` (сдать и
проверить), `release` (принять), `refund` (отклонить), `verify` (проверить
чужую квитанцию), `trust` (репутация). Квитанция подписывается и
проверяется третьей стороной без доступа к мосту.

## Оплата

20 проверок в сутки — бесплатно и без регистрации. Дальше $0.005 за вызов
(x402, USDC в сети Base) или $9 за 30 дней без ограничений
(`POST https://attest.rta.lat/subscribe`). Для Индии — те же 30 дней за $3
(`POST https://attest.rta.lat/subscribe?plan=ppp`).

Подписку кладут в заголовок `X-ATTEST-ENTITLEMENT`, оплату вызова — в
`PAYMENT-SIGNATURE` (v2) или `X-PAYMENT` (v1).
