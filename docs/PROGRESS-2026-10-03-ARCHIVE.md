# PROGRESS · attest

**Что это:** детерминированная проверка артефактов ИИ-агентов. Не LLM-обёртка:
инъекции, нарушения схемы, происхождение — по правилам. Вердикт `accept` /
`review` / `reject` + подпись.

**Позиционирование (решение владельца 2026-10-02):** экономика переливается
в автоматизацию под управлением ИИ, продукт настраивается на это. Проверка
артефактов — слой доверия, который понадобится каждому, кто автоматизирует.

## Что сделано в этом заходе

Главное: **до этого захода сервиса не существовало**. Была библиотека, которой
не мог воспользоваться никто, кроме нас. Продукт без входа не зарабатывает.

1. **HTTP-сервис** (`attest/service.py`): `POST /verify`, `GET /health`,
   `GET /pricing`, `GET /stats`. Только стандартная библиотека — ноль
   зависимостей, как и во всём проекте.
2. **Страница для клиента**: вставил артефакт → вердикт, доверие, находки,
   подпись. Без регистрации, без ключа. Две кнопки: проверка и пример атаки.
3. **Бесплатный тариф**: 20 проверок в сутки на адрес клиента. Не маркетинг,
   а способ узнать спрос до того, как он станет дорогим.
4. **Монетизация**: при исчерпании лимита — `402` с настоящим x402 v2
   челленджем в заголовке `Payment-Required` (0.001 USDC, Base).
5. **Автолистинг**: челлендж несёт расширение `bazaar`, поэтому после первой
   оплаты фасилитатор каталогизирует сервис сам. Регистрация не нужна.

## Приём оплаты (2026-10-03, закрыт бесплатно)

Главный был пробел: сервис умел **просить** деньги, но не умел их **принимать**.
Закрыт на бесплатных инструментах, без единой транзакции.

`attest/payment.py`: разбор `X-PAYMENT`, сверка с выставленным счётом,
криптографическая проверка подписи, защита от повтора.

| Защита | От чего |
|--------|---------|
| Сумма сверяется с челленджем | клиент дописал `value: "1"` |
| Получатель сверяется | платёж ушёл не туда |
| Сеть сверяется | оплата в другой сети |
| Подпись сверяется с digest'ом | подпись чужого кошелька |
| `validBefore`/`validAfter` | просрочено или ещё не действует |
| nonce не повторяется | перезапуск одной и той же оплаты |
| порядок проверок | криптография только после дешёвых сравнений |

Живой прогон 2026-10-03:
```
1) бесплатно           HTTP 200  ACCEPT  paid=False
2) без оплаты          HTTP 402  бесплатный лимит исчерпан (1/1)
3) с настоящей оплатой HTTP 200  ACCEPT  paid=True  payer=0x2BA61C53…
4) повтор подписи      HTTP 402  этот nonce уже использован
```

### Два бага, найденных сверкой с эталоном

Оба тихо сломали бы каждую настоящую оплату:

1. **Тип EIP-712 был собран как `name string` вместо `string name`.** Хеш
   получался правдоподобным, но другим: подпись не сходилась. Домен и
   struct-hash по отдельности совпадали с эталоном — расходился только
   финальный digest, поэтому пришлось разбирать по шагам.
2. **Восстановление адреса применяло префикс EIP-191.** Подпись ставится по
   сырому EIP-712 digest; с префиксом восстанавливается другой адрес, и
   сервис счёл бы каждую оплату поддельной.

Оба нашлись только потому, что digest сверялся с независимой реализацией
`eth_account`. Собственный тест на собственный код был бы self-confirming
и прошёл бы при обоих багах.

**Вывод, который стоит запомнить:** деньги не проверяются тестами, написанными
тем же кодом. Нужна вторая, независимая реализация, с которой сверяем.

## Протокол проверен настоящим фасилитатором (2026-10-03)

Самая сильная проверка из возможных бесплатно: платёж, собранный **нашим**
кодом, отправлен живым фасилитатору `https://x402.org/facilitator`, который
проверяет его настоящим контрактом USDC в сети Base Sepolia.

```
наш счёт: eip155:84532, 5000 атомов, домен "USDC"
наша проверка: ПРИНЯТО, плательщик 0x3685a315E9648Db1C65013567D599C1A0834e4D6
фасилитатор:  invalid_exact_evm_insufficient_balance
              ERC20: transfer amount exceeds balance
```

Адрес плательщика у нас и у фасилитатора **совпал**. Ответ контракта означает:
подпись принята, домен верен, кодировка верна. Единственная причина отказа —
у тестового кошелька ноль USDC. Больше неизвестных не осталось: как только
появится токен, расчёт пройдёт.

### Что выяснилось при проверке

| Факт | Источник |
|------|----------|
| В v2 `scheme`, `network`, `amount` лежат в блоке `accepted`, не наверху | ответ фасилитатора |
| Заголовок оплаты в v2 — `PAYMENT-SIGNATURE` (в v1 был `X-PAYMENT`) | документация x402 |
| Форма тела `/verify`: `paymentPayload` + плоский `paymentRequirements` | подбором, 6 вариантов |
| На Base mainnet токен в домене `USD Coin`, на Base Sepolia — `USDC` | name() в сети + подпись |
| `x402.org/facilitator` держит EVM только на Base Sepolia | `/supported` |
| mainnet-EVM поддерживает PayAI-фасилитатор | `/supported` |

### Три бага, найденные этой проверкой

1. **Парсер искал `scheme` на верхнем уровне.** В v2 его там нет — он внутри
   `accepted`. Наш сервис отверг бы **каждую настоящую оплату**.
2. **Домен был единственной константой для mainnet.** На Base Sepolia имя токена
   другое — «USDC» вместо «USD Coin». Подпись не прошла бы с первого раза.
3. **Заголовок читался только `X-PAYMENT`.** Актуальная спецификация v2
   использует `PAYMENT-SIGNATURE`.

Тест на дрейф таблиц доменов между `attest` и `agentpay` сработал сразу после
правки №2 и заставил синхронизировать обе таблицы.

### Дефекты, найденные вживую (а не в тестах)

| Дефект | Почему это важно | Как закрыто |
|--------|------------------|------------|
| `/pricing` обещал 20 проверок при реальном лимите 3 | враньё клиенту | лимит берётся из живого счётчика |
| На странице светились `{free_limit}` и `{{…}}` | сломанная страница | шаблон рендерится настоящим числом; тест ищет утечки |
| 413 без чтения тела рвал соединение | клиент получал ошибку вместо ответа | тело дочитывается и выбрасывается |
| Опечатка в адресе кошелька роняла сервис трейсбеком | падение из-за конфига | ошибка конфигурации → внятный 402 без челленджа |

Три из четырёх нашлись только на живом запуске. Тесты на них не смотрели.

## Монетизация: как это устроено

| Уровень | Цена | Что | Маржа на вызов |
|---------|------|-----|----------------|
| Пробный | 0 | 20 проверок в сутки, полный функционал | минус $0.00146 × 20 = **$0.03 в сутки** |
| За вызов | **0.005 USDC** | сверх лимита, оплата по x402 в Base | +$0.00354 |
| Подписка | 9 USDC/мес | без лимита, для конвейера в CI | весь чек |

### Цена была ниже себестоимости — исправлено 2026-10-02

Рекомендованная цена **0.001 USDC** оказалась **меньше стоимости самого расчёта**.
Измерено на Base вживую: `gasPrice` 0.006 Gwei, `transferWithAuthorization`
≈ 90 000 газа, ETH $2702 → **$0.00146 за вызов**. На каждом вызове мы теряли
$0.000459. Выручка росла, денег не было.

Цена поднята до 0.005 USDC (вдвое ниже медианы каталога $0.01), защита в коде:
`check_price_covers_cost()` не даст назначить цену ниже себестоимости ×2.

**Честный вывод по экономике:** при 0.005 USDC нужно ~28 000 вызовов на $100
в месяц; при 0.01 — ~11 700. Микроплатежи на Base плохо масштабируются на
малом объёме. Реальные деньги — в подписке: 11 платящих клиентов дают $100.
Поэтому подписку $9 стоит продвигать основной, а не за вызов.

**Конкуренты в нашей нише уже есть:**
`relay402.../api/security-prompt-injection-*` — 0.02 USDC (проверка инъекций),
`.../security-secrets-check` — 0.02, `.../security-pypi-risk` — 0.015,
`julie.freysa.dev/api/audit` — 0.01, `.../preflight` — 0.004.

Отличие `attest`: не текст на инъекции, а **проверка артефакта агента** —
схема + происхождение + подпись, детерминированно и с юридически значимым
результатом. Этого в каталоге нет, но и спроса на артефакты мы пока не видели.

**Проверено по документации x402 (30.09.2026):** листинг бесплатный,
регистрации нет, цену назначает продавец, каталогизация автоматическая при
обработке платежа с расширением `bazaar`. Официальный фасилитатор —
`https://x402.org/facilitator`. Сети: Base, Base Sepolia, Solana.

Отсюда: **посредников нет**. Ни модерации, ни заявки, ни ожидания. Первый
платящий клиент одновременно публикует сервис в каталоге, где его находят
агенты. Цикл замкнут сам на себя.

Отобраны по практическим требованиям каталогов MCP (сентябрь 2026), не по

| mcp.so (~20 тыс.) | только платный тариф, качество спорное | $39 | 🔴 не стоит |

**LobeHub — отказ осознанный:** требует GitHub OAuth с правом чтения и записи
**всех** репозиториев, включая приватные. Проверка владельца, которую другие
каталоги делают TXT-записью в домене, здесь стоит доступа к вашему коду.

Требования сканеров, которые закрыты в коде:

- `resources/list` и `prompts/list` возвращают пустые списки, а не «метод не
  найден» — иначе карточка выглядит сломанной;
- у инструмента полные аннотации `title` / `readOnlyHint` / `destructiveHint` /
  `openWorldHint` — без них Anthropic не примет листинг;
- отказ проверки возвращается как результат инструмента с `isError: true`,
  а не как протокольная ошибка: рецензент запускает инструмент и «Internal
  error» читается как поломка.

## Следующий шаг

Технических неизвестных не осталось. Дальше нужны два ваших действия:

1. **Домен** — заменить `REPLACE_WITH_DOMAIN` в `server.json`,
   `gemini-extension.json`, `llms-install.md`, `README.md`; подтвердить
   владение TXT-записью; после этого листинг во всех каталогах бесплатен.
2. **USDC в сети Base** — принять первую настоящую оплату.

Оба сводятся к одному действию с вашей стороны. Пока их нет, дальнейшая
работа — писать манифесты с заглушками, что и сделано.
